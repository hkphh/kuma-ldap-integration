# KUMA LDAP‑интеграция

## Что это?

KUMA умеет собирать из Active Directory (AD) данные о пользователях.  
Некоторые возможности недоступны через веб‑интерфейс и не могут быть использованы в правилах.  
С помощью скрипта можно импортировать любые поля из внутренней SQLite‑базы и помещать их в словари/списки KUMA.

> **Важно** – скрипт рекомендуется размещать на Core‑сервере KUMA, чтобы он имел доступ к базе данных и API.

---

##  Предварительные требования

| № | Что нужно установить |
|---|----------------------|
| 1 | Python 3.8+ (или любой другой, совместимый с `requests`) |
| 2 | Библиотека `requests` (`pip install requests`) |
| 3 | Доступ к внутренней SQLite‑базе KUMA |
| 4 | ID словаря (DICT_ID) – скопировать из веб‑интерфейса KUMA |

---

##  Установка

```bash
git clone https://github.com/hkphh/kuma-ldap-integration
cd kuma-ldap-integration
```

---

##  Конфигурация

1. **Укажите ID словаря**  
   В файле `config.py` (или переменной окружения) задайте:

   ```python
   DICT_ID = "<DICT>"  # замените на фактический ID словаря из веб‑интерфейса
   ```

2. **Настройте SQL‑запрос**  
   В скрипте (`import_ldap.py`) найдите блок `sql` и отредактируйте его. 
   В моем случае выводится логин|домен пользователей из админиских групп:

   ```python
   sql = """
       SELECT sam_account_name || '|' || domain
       FROM accounts
       WHERE archived = 0
         AND (
             member_of LIKE '%SuperAdminGroup%'
             OR member_of LIKE '%Remote Assistants%'
         );
   """
   ```

---

##  Запуск

```bash
python3 code.py
```

После выполнения скрипта вы увидите сообщение вида:

```
HTTP‑код: 200 – импорт выполнен успешно
```

Если код отличается от `200`, проверьте лог‑сообщения в консоли – там будет указана причина ошибки.
